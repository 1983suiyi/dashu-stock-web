# 大数选股工具技术方案

> 本文记录当前代码实现，不是目标态设计。涉及外部行情时，接口可用性和字段口径以实际返回为准。

## 1. 系统目标与边界

应用将公开 A 股财务、估值与行情数据整理为可解释的筛选和组合工作台，并支持账号隔离、持仓管理、市场阶段回看。

- 市场和个股数据来自东方财富、腾讯公开网页接口，不承诺官方 API 的 SLA。
- React 端负责界面、评分、行业汇总和牛熊阶段计算。
- Node.js 服务端负责行情代理、历史数据缓存、账号鉴权、用户数据持久化和静态文件托管。
- 不在自动刷新中重拉全市场列表或个股历史 K 线。

## 2. 总体架构

```text
用户端 index.html（React / TypeScript）       管理端 admin.html（独立 MPA 入口）
             │                                           │
             ├── 东方财富公开接口（财务、估值、行业）     ├── /api/admin/*
             ├── /api/index-snapshot                     │
             ├── /api/index-history                      │
             ├── /api/kline                              │
             └── /api/auth/*、/api/user-data/*、市场温度 ─┘
                                  │
                      server/index.mjs（node:http）
                       ├── server/kline.mjs
                       ├── server/index-history.mjs
                       ├── server/industry-cycle.mjs
                       ├── server/stock-valuation.mjs
                       └── server/db.mjs（node:sqlite）
```

开发环境由 `vite.config.ts` 将 API 请求转给同一批服务端模块；生产环境由 `server/index.mjs` 提供 API 和 `dist/` 静态资源。接口逻辑应保持开发、生产共用，避免两套行为逐渐偏离。

## 3. 页面与核心业务

| 页面/模块 | 输入 | 核心处理 | 输出 |
| --- | --- | --- | --- |
| 市场概况 | 东方财富全市场数据、上证快照 | 市场温度、仓位区间、市场统计 | 市场状态、市场温度、上证点位及建议仓位 |
| 大数评分 | PB、PE、现价、财务质量、股息及风险因子 | 300 分制评分、硬过滤、行业分层推荐 | 评分表（含扫雷宝与现金含量）、推荐组合、淘汰原因 |
| 持仓与汇总 | 用户持仓、现金、资产、资金流水 | 组合权重、盈亏与行业暴露统计 | 持仓清单和汇总 |
| 细分行业/周期行业 | 行业、PB/PE 时间序列 | 行业归一化、周期性和估值区间统计 | 行业对比与历史分位 |
| 个股估值图 | 个股季度 PE/PB 序列 | 负 PE 置空，识别连续亏损区间 | PE/PB 曲线、历史分位、亏损灰色区间 |
| 牛熊阶段 | 上证指数、深证成指、创业板指、科创50日线 OHLCV | 基于收盘价的 zigzag 反转识别 | 当前阶段、历史阶段、转折点和局部 K 线 |
| 归档/AI | 用户工作台数据、分析结果 | 按用户保存快照，生成辅助摘要 | 历史归档和 AI 摘要 |
| 管理端 | 管理员会话 | 角色鉴权、邀请码/用户/公共数据管理和审计 | 独立管理界面 |

### 3.1 扫雷口径（硬过滤 vs 仅扣分）

扫雷宝满分 100，四项分别处理；界面上硬过滤项用红色、仅扣分项用黄色、数据缺失用灰色。

| 项 | 数据来源 | 处理方式 |
| --- | --- | --- |
| 资产负债率 | `RPT_DMSK_FN_BALANCE` | 高于「行业中位数 × (1 + 宽容幅度，默认 15%)」即硬过滤剔除 |
| 商誉 / 净资产 | `RPT_GOODWILL_STOCKDETAILS` | `>= 20%` 硬过滤；5%~20% 按超出比例连续扣分（最多 70 分） |
| 股权质押比例 | `RPT_CSDC_LIST_NEWEST` | `>= 20%` 硬过滤；10%~20% 按超出比例连续扣分（最多 30 分） |
| 经营现金流质量 | `RPT_DMSK_FN_CASHFLOW` + `RPT_LICO_FN_CPD` | 仅扣分，不剔除 |

经营现金流质量口径：现金含量 = 经营活动现金流净额 ÷ 归母净利润，阈值 `0.5`。

- 经营活动现金流净额为负：扣 18 分；同期归母净利润也为负时扣 25 分（该项上限）。
- 现金含量低于 `0.5`：按差额线性扣分，最多 15 分。
- 归母净利润非正或数据缺失：不计算比值、不扣分（亏损本身已由 PE 置空、估值不参与评分体现）。

分数 = `100 − 商誉扣分 − 质押扣分 − 现金流扣分`，下限 0。数据缺失一律不扣分，避免公开接口字段缺失造成误杀。
界面上「N 项触发，按规则暂时剔除」只统计硬过滤项；仅扣分项在详情卡片显示 `-N 分` 的黄色标注，评分表排雷列以「现」字徽标标注。

## 4. 指数快照自动刷新

### 4.1 请求流程

```text
App 挂载
  ├── 先读当日浏览器缓存，快速展示上次有效值
  ├── 立即请求 GET /api/index-snapshot?symbol=sh000001
  └── 页面可见时每 60 秒请求一次
          └── server/kline.mjs → 腾讯 qt.gtimg.cn 行情快照
```

- 快照 API 只执行报价请求，不执行 `/api/kline` 中用于个股三年低点的历史请求。
- 前端用 in-flight 标记防止慢请求重叠；浏览器标签页隐藏时跳过轮询，恢复可见时立即刷新。
- 服务端按 symbol 缓存 30 秒，并对同 symbol 的并发请求共享进行中的 Promise。
- 拉取失败时保留上次成功的点位；页面展示自动刷新周期和最近成功更新时间。
- 60 秒是低频展示间隔，不是逐笔行情。腾讯行情接口可能存在自身更新延迟或限流。

### 4.2 接口数据

`GET /api/index-snapshot?symbol=sh000001` 返回腾讯快照解析结果，当前界面使用：

- `lastClose`：腾讯报价字段中的当前指数点位；
- `high1y`、`low1y`：近一年高低点；
- 不需要的历史 K 线字段为空。

该接口是新增路由；`/api/kline` 保留原用途，继续服务个股现价、一年高低和历史低点补齐。

## 5. 牛熊阶段与 K 线

- 数据：`/api/index-history?symbol={指数代码}&years=20`，向腾讯指数日线接口分页获取近 20 年 OHLCV；页面可切换上证指数（`sh000001`）、深证成指（`sz399001`）、创业板指（`sz399006`）、科创50（`sh000688`）。
- 分页：每页最多 2000 条，最多 4 页；服务端进程内缓存 6 小时。
- 转折算法：以日线**收盘价**运行 zigzag。自高点回撤达到阈值确认顶，自低点反弹达到阈值确认底；默认 20%，可选 20%/25%/30%/35%。
- 阶段归纳：低点到高点为牛市，高点到低点为熊市；最后一个转折点到最新交易日标为进行中。
- 图表：全周期折线仍显示收盘价；转折卡片和悬停信息同时展示转折日收盘、最高、最低。盘中最高/最低用于价格说明，不会悄悄替换收盘价转折口径。
- 局部 K 线窗口可选转折日前后各 3、6、12 个月。

## 6. 数据存储与缓存

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 股票池、估值结果及全量 K 线进度 | 浏览器 `localStorage` | 本地缓存；不会因指数自动刷新而重新下载 |
| 持仓、现金、总资产、资金流水、个人归档 | 浏览器本地缓存 + SQLite `user_data` | 按当前登录用户隔离；登录时云端数据同步到本地 |
| 市场温度 | SQLite `market_temperature` + 浏览器缓存 | 公共数据，按日期保存 |
| 指数当日快照 | 浏览器当日缓存 + 服务端 30 秒内存缓存 | 缓存失效不影响页面继续显示上次有效值 |
| 指数历史、行业周期、估值历史 | 服务端进程内或文件缓存 | 只用于减少重复上游请求，不作为用户数据真相源 |
| 账号、会话、验证码、邀请和审计 | SQLite | 由 `server/db.mjs` 初始化和维护 |

用户数据采用通用 JSON KV：`user_id + kind` 为主键，当前 kind 包括 `holdings`、`cash`、`totalAssets`、`capitalEvents`、`archives`。同步策略是本地优先写入、异步云端保存；登录时以云端数据覆盖相应本地数据。

## 7. API 目录

| 路径 | 用途 | 调用频率/备注 |
| --- | --- | --- |
| `GET /api/index-snapshot` | 上证快照 | 前端每 60 秒；服务端缓存 30 秒 |
| `GET /api/index-history` | 指定指数的历史日线 | 页面加载或手动刷新；服务端按指数代码缓存 6 小时 |
| `GET /api/kline` | 股票快照和个股历史低点 | 按候选/批次需要调用，不用于指数轮询 |
| `GET /api/industry-cycle` | 行业周期统计 | 页面需要时读取 |
| `GET /api/stock-valuation` | 个股 PE/PB 历史 | 按个股诊断需要读取 |
| `/api/auth/*` | 注册、登录、会话和注销 | 会话接口 |
| `/api/user-data/:kind` | 当前用户数据读取/覆盖写入 | 需要登录；写入校验 CSRF 请求头 |
| `/api/market-temperature` | 公共市场温度读写 | 需要登录 |
| `/api/admin/*` | 管理员功能 | 强制检查 `admin` 角色 |

## 8. 安全与部署

- 账号和会话由服务端验证；用户私有数据查询以当前会话用户 ID 为边界，客户端不能指定其他用户 ID。
- 用户数据写接口校验 `X-Requested-With: XMLHttpRequest`；管理路由在服务端强制校验管理员角色。
- 生产部署启用 HTTPS，保护会话 Cookie 与登录流量；数据库和 `.env` 不应放入公开静态目录或提交到代码仓库。
- 服务端使用 Node 内置 `node:sqlite`，运行要求 Node.js `>=22.13`；建议使用 Node.js 24 LTS。
- 构建：`npm run build`；静态资源和 API 同进程启动：`npm start`；默认端口 8787，可用 `PORT` 覆盖。

## 9. 验证与限制

- 自动刷新验证应使用单次请求和缓存命中检查，不对公开行情源做高频压力测试。
- 开发和生产均需检查 `/api/index-snapshot`、`/api/index-history` 路由。
- 公开接口不是稳定商业 API，字段、限频和可用性可能变化；请求失败需保留缓存并提供可诊断日志。
- 市场关闭时指数值不会因为缩短轮询周期而变化；页面每分钟更新不代表数据源每分钟产生新行情。
- 收盘价转折适合阶段统计，但与盘中历史绝对高低点不同；界面同时显示当日 OHLC，防止把口径混淆。
- 新增财务字段（如经营现金流）只在重新拉取全市场数据后出现；旧浏览器缓存缺少该字段时按缺失处理（不扣分），不会因口径升级而误杀已有结果。
