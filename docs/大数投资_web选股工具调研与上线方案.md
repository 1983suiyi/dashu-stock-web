# 大数投资 Web 选股管理工具调研与上线方案

## 1. 项目目标

围绕《大数投资》公开可得的思想，设计一套面向 A 股的 Web 端选股管理工具。目标不是“复刻书籍原文”，而是将书中的核心方法抽象成：

1. 可配置的选股规则
2. 可解释的评分与淘汰机制
3. 可扩展的数据接入层
4. 可部署的前端工作台

## 2. 公开资料中可以确认的核心方法

基于出版社页面、作者公开访谈、公开目录与试读页，可以确认以下信息：

### 2.1 核心原则

- 组合投资
- 低估值建仓
- 长期持有

这些原则在出版社与作者公开介绍中均反复出现。

### 2.2 组合构建思路

- 通过概率抽样、尤其是分层抽样来选择少数上市公司
- 目标是“拟合全部上市公司”的净资产和盈利水平
- 作者公开表述提到，实践上可通过 30 家以上样本来实现整体拟合

### 2.3 估值与交易准则

公开目录与试读页可确认：

- 常用估值方法包括 `PE / PB / PS / 内在价值法`
- 存在“多项因素估值算法”
- 交易准则中明确包含：
  - 降低投资成本准则
  - 永续投资准则
  - `2/3` 上限准则
  - 长期持有法则

### 2.4 市场整体估值的重要性

试读页中明确出现“依据股市整体估值水平进行交易”的章节，因此产品上应保留“市场估值温度”和“建仓节奏”联动，而不是只看个股。

## 3. 本工具如何将方法抽象为可执行规则

当前原型将方法拆为四层：

### 3.1 股票准入层

先做硬过滤，解决“哪些股票连候选池都不该进”的问题：

- 非 ST
- 上市年限不低于阈值
- ROE 不低于阈值
- PB / PE / PS 不高于阈值
- 资产负债率不高于阈值
- 无形资产占比不高于阈值

### 3.2 评分层（三好学生评分，300 分制）

评分体系已**替换为「大数模拟器」的真实「三好学生评分」**，算法由该站点公开前端产物 `main.dart.js`
逆向还原（详见 3.2.1），而非自拟权重。

- PB 得分（0~100）：PB 落在 `[q, 2q]` 区间，下沿满分、上沿 0 分
- PE 得分（0~100）：PE 落在 `[10q, 20q]` 区间，口径与 PB 联动
- 一年内涨幅得分（0~100）：距一年内最低价涨幅越低分越高
- **三好学生评分 = 三项之和（满分 300）**
- **绝对胜算概率 = 总分 / 3**，因此 200 分门槛 ≡ 66.67% ≡ 2/3 胜算

#### 3.2.1 还原出的评分公式（非推测）

```text
q        = 历史折扣 >= 1 ? 1 : 0.618 + 历史折扣 × 0.382
bta(lo,hi,v) = v >= hi ? 0 : (v <= lo ? 1 : 1 - (v - lo) / (hi - lo))

PB 得分  = bta(q,      2q,      PB)  × 100
PE 得分  = bta(10q,    20q,     PE)  × 100
涨幅得分 = 涨幅 <= 0 ? 100 : max(0, 100 - 200 × 涨幅)
涨幅     = (现价 - 一年内最低价) / 一年内最低价

三好学生评分   = PB 得分 + PE 得分 + 涨幅得分          （满分 300）
绝对胜算概率   = 三好学生评分 / 3                     （%）
```

筛选口径同样还原自该产物：`>200 分`、`股息率 > 1%`、`资产负债率 < 行业资产负债率中位数`、
满配过滤时单行业持仓 `> 3%`。

**数据缺口处理**：一年内最低价由 K 线代理补齐；股息率、商誉占净资产当前数据源未提供，
保持 `null`（显示 `—`）且**不参与淘汰判定**，避免被误判为 0 而错杀。

### 3.3 组合层

不直接按总分机械取前 N，而是先按行业分组，优先为每个行业挑出高分样本，再补足目标持仓数。这是对“分层抽样”最适合产品化的一种表达。

### 3.4 仓位层

根据全市场 PB 判断市场状态，并把权益仓位限制在 `2/3` 以下：

- 市场深度低估：接近策略上限
- 市场中性偏低估：正常滚动建仓
- 市场中性偏高估：保留更多现金
- 市场明显高估：停止扩张仓位

## 4. 功能清单

当前 Web 工具已实现：

- 市场状态总览与估值温度联动
- 方法论摘要卡片
- 规则参数配置（历史折扣、评分门槛、股息率下限、单行业上限、总仓位上限、K 线天数、候选上限）
- 一键拉取全市场真实数据（估值 + 财务 + 行业）
- **Web 端直接展示选股列表**（大数评分表：PB/PE/涨幅分项得分、三好学生评分、胜算概率、资产负债率对比、状态、风险提示）
- **导出总评分为 CSV**（「大数评分表」「大数持仓」两张表，UTF-8 BOM 防 Excel 乱码）
- 推荐组合表与目标权重分配
- 淘汰原因与缺失字段解释
- CSV 股票池导入 / 演示数据回退
- K 线代理（`/api/kline`）补齐一年内最低价

## 5. 为什么当前版本先做前端原型

这是一个更稳妥的交付路径，原因有三点：

1. A 股真实财务和估值数据源的可用性、授权和频率差异较大
2. 书中很多内容适合抽象成“可调规则”，不必等数据接入完才开始产品设计
3. 先固化前端工作台，可以尽早验证用户实际使用方式

## 6. 数据接入建议

### 6.0 已确定的数据源（实测结论）

已选定并接入 **东方财富数据中心公开接口**（`datacenter-web.eastmoney.com`），实测结论如下：

| 维度 | 实测结果 |
| --- | --- |
| 费用 | 免费，无需注册、无需 token |
| 跨域 | 响应头返回 `Access-Control-Allow-Origin: *`，浏览器可直连，**无需自建后端** |
| 覆盖 | 5223 只 A 股，128 个行业 |
| 速度 | 全市场拉取约 2.4 秒 |
| 字段覆盖 | PB / PE / 价格 100%，ROE 98.7%，资产负债率 99.9% |

使用的三张报表与字段：

| 报表 | 关键字段 | 对应本工具字段 |
| --- | --- | --- |
| `RPT_VALUEANALYSIS_DET` | `PB_MRQ` / `PE_TTM` / `PS_TTM` / `CLOSE_PRICE` / `TOTAL_MARKET_CAP` / `BOARD_NAME` | `pb` / `pe` / `ps` / `price` / `marketCap` / `industry` |
| `RPT_DMSK_FN_BALANCE` | `DEBT_ASSET_RATIO` | `debtRatio` |
| `RPT_LICO_FN_CPD` | `WEIGHTAVG_ROE` | `roe` |

实测踩到的三个接口约束（已在代码中处理）：

1. 这些报表接口**必须带 `filter` 参数**，否则返回 `success:false / 服务器繁忙`。
2. `RPT_LICO_FN_CPD` 的日期字段是 `REPORTDATE`，**没有下划线**，与其他报表的 `REPORT_DATE` 不一致。
3. 非交易日查询返回 `code:9201 / 返回数据为空`，因此交易日需用「区间 + 倒序」方式推导。

**未覆盖字段**：股息率、商誉占净资产。
处理方式：显示为 `—` 且**不参与淘汰判定**（避免被当成 0 分误伤），可通过 CSV 补充。

### 6.0.2 K 线数据源（一年内最低价）

「涨幅得分」需要一年内前复权最低价，该字段东财估值表没有，因此单独接入 K 线代理：

| 候选 | 实测结果 | 结论 |
| --- | --- | --- |
| 东方财富 `push2his` | 响应体与响应头均为空，**不可用** | 弃用 |
| 腾讯 `web.ifzq.gtimg.cn` 前复权日线 | 单只约 53ms，数据完整 | **已采用** |

实现要点：

- 腾讯接口**不支持批量**（分号分隔多标的返回 `param error`），因此改为**单标的一次请求 + 并发**（默认并发 24）。
- 开发环境（`vite.config.ts`）与生产环境（`server/index.mjs`）复用同一份 `server/kline.mjs` 逻辑，避免两份实现漂移。
- **两阶段剪枝**：总分 = PB + PE + 涨幅，涨幅分上限 100，故 `PB+PE <= 门槛-100` 的股票一定不及格，无需拉 K 线。先按 PB+PE 筛候选，再只对候选补 K 线，结果精确且不丢候选。

### 6.0.3 其他候选数据源对比

| 数据源 | 免费 | 是否需后端 | 结论 |
| --- | --- | --- | --- |
| 东方财富 `datacenter-web` | ✅ | ❌ 浏览器可直连 | **已采用** |
| AkShare | ✅ | ✅ 必须（Python 库） | 备选，可与后端结合 |
| BaoStock | ✅ | ✅ 必须（Python 库，需 login） | 备选，财务字段规范 |
| Tushare | ⚠️ 名义免费 | — | 免费仅 120 积分，财务因子需 2000 积分（约 ¥200/年），**不属免费方案** |

## 7. 推荐技术方案

### 7.1 当前已实现

- 前端：`React + TypeScript + Vite`（`tsc -b && vite build`）
- 数据：东方财富公开接口（浏览器直连）+ 腾讯 K 线（本地代理）
- 后端：零依赖 `node:http` 服务（`server/index.mjs`），提供 `/api/kline` 与 `dist/` 静态托管
- 开发环境：`vite.config.ts` 挂载同一份 K 线逻辑，`npm run dev` 即可联调
- 部署形态：可用 `npm start` 单进程同时提供接口与静态站点

### 7.2 下一步推荐架构

- 前端：`React / Next.js`
- 后端：`Node.js + PostgreSQL`
- 数据任务：`Python + AkShare/Tushare + 定时任务`
- 部署：
  - 外网演示：`Vercel`
  - 企业内网：`Nginx + Docker`

## 9. 风险与边界

### 9.1 版权边界

本项目不应复制书中大段原文或受版权保护的完整算法描述。当前方案只使用公开目录、出版社内容简介、公开访谈与有限试读信息做方法抽象。

### 9.2 合规边界

工具定位应为“研究与管理辅助”，而不是向不特定公众提供投资建议服务。

### 9.3 数据边界

若接入第三方金融数据源，需要确认其授权范围、调用频率限制与商用条款。
